# 親の機能不全トリガー (Parent Down Trigger)

**マニフェスト価値:** 強靭性 (Resilience)
**マニフェストルール:** ルール2
**優先度:** 高 - 緊急時プロトコルに次ぐ

> 2026-11-06（E-3。台帳 G-71）：DB を読む箇所を今の構成（読み取りの包み・仮名・スキルの照会）に合わせた。照会の文はスキルの側に一つだけ持ち、ここには写さない。

---

## トリガー条件

以下の状況を示す入力があった場合、このプロトコルを発動する。

**キーワード:**
- 「母が入院した」「父が倒れた」「親が認知症になった」
- 「一人になった」「家に誰もいない」
- 「介護が必要になった」「施設に入った」
- 「亡くなった」「死亡した」

本人は仮名（`displayCode`。例：C-ZZZZZZ）で呼ぶ。親を含む人は、包みが返す人の ID と続柄で示す（実名・電話・住所は Claude から出せない）。

---

## 実行手順

### フェーズ1：緊急情報の確認（emergency.mdが先行している場合はスキップ）

→ `emergency-protocol` スキルの照会 1 を流し、禁忌（`LifeThreatening` → `Panic` → `Discomfort`）と推奨ケアを最初に確かめる。

連絡先は「手元の緊急連絡カードと SOS の画面で確かめる」と一行で書く。

### フェーズ2：親の担当タスク（CareRole）の特定

→ `resilience-checker` スキルの照会 1（親と、親が担っている役割）を `nest-personal` の `read_personal_cypher` で流す。

**典型的なCareRole:**
- 金銭管理（お小遣い管理、家賃支払い）
- 食事準備（調理、買い出し）
- 服薬管理（薬の準備、声かけ）
- 送迎（作業所、通院）
- 身辺介助（入浴、着替え）
- 精神的安定（パニック時の対応、日常の見守り）

### フェーズ3：代替手段の検索

→ `resilience-checker` スキルの照会 2（役割ごとの代わりの担い手）を流す。代わりは、人（`Person`）か機関の関わり（`Involvement`）。機関の名前は資源の側で引く。

代替手段が見つからない場合は、`provider-search` スキルで資源の側（事業所の公開情報）から候補を探す。

**サービス種類のマッピング:**
| CareRole | 対応する福祉サービス |
|----------|---------------------|
| 食事準備 | 居宅介護（家事援助）、配食サービス |
| 金銭管理 | 日常生活自立支援事業、成年後見制度 |
| 服薬管理 | 居宅介護、訪問看護 |
| 送迎 | 移動支援、行動援護 |
| 身辺介助 | 居宅介護（身体介護） |
| 精神的安定 | 地域定着支援、短期入所 |
| 見守り全般 | グループホーム、自立生活援助 |

### フェーズ4：レジリエンス・レポートの作成

全ての情報を統合して、以下の形式でレポートを提示する（`resilience-checker` の報告の形）。

```
## 🔄 レジリエンス・レポート
**対象:** C-……
**発生事象:** 親（人の ID・続柄）の[状況]
**日付:** [日付]

### 影響を受けるタスク一覧

| # | タスク | 頻度 | 代替手段 | ステータス |
|---|--------|------|----------|-----------|
| 1 | 食事準備 | 毎日 | 居宅介護の関わり（機関の名前は資源の側） | ✅ 代わりあり |
| 2 | 金銭管理 | 月2回 | 未確定の関わりだけ | ⚠️ 要確認 |
| 3 | 送迎 | 週5 | なし | 🚨 代わりなし |

### 即座のアクション
- [代わりなしのタスクに対する手配の案。決めるのは職員]

### 中長期の対応
- [支援体制の見直し提案]
```

### フェーズ5：フォローアップ

- 必要に応じてキーパーソンへの連絡を促す
- 代替手段が全て確保されるまで、定期的な確認を提案する
- 状況の変化（親の退院等）があれば、CareRoleの再評価を行う

→ 詳細なレポート生成は `workflows/resilience_report.md` を参照

---

## CareRoleが未登録の場合

Parent Down Triggerが発動したが、CareRoleがデータベースに無い場合：

1. **確認の状況を見る:** `resilience-checker` の照会 3。確認の記録（`Review`、領域 `CareRole`）が無ければ「親の担っている役割は未確認」と出す。「役割なし」と書かない
2. **警告を発する:**
   「⚠️ 親が担っている役割（CareRole）が未確認です。緊急の支援調整が必要です。」
3. **ヒアリングを開始する:**
   「親御さんが日常的に行っていたことを教えてください。」
   - 食事は誰が作っていましたか？
   - お金の管理は？
   - 通院の送り迎えは？
   - 薬の管理は？
4. **登録は案にする:** 聞き取った話は `narrative-extractor` で書き込みの案（JSON）にし、職員が確かめてゲート（`nest/gate/`）に通す。Claude は DB に書かない。AI が作ったものは未確定で入る

## 実行の順の例（架空）

```
入力: 「C-ZZZZZZ さんのお母さんが急病で入院しました。家には本人だけで、食事の準備ができていません。」

実行順序:
1. emergency-protocol の照会 1 → 禁忌・推奨ケア
2. resilience-checker の照会 1 → 親が担う「食事準備」「服薬管理」等
3. resilience-checker の照会 2 → 登録済みの代わりの担い手
4. provider-search → 代わりなしの役割の候補（居宅介護など）
5. レジリエンス・レポート → 一覧表で状況を示す
```
