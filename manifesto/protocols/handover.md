# 担当者引き継ぎプロトコル (Handover Protocol)

**マニフェスト価値:** 継続性 (Continuity)
**優先度:** 高

> 2026-11-06（E-3。台帳 G-71）：DB を読む箇所を今の構成（読み取りの包み・仮名・スキルの照会）に合わせた。照会の文はスキルの側に一つだけ持つ。

---

## トリガー条件

- 担当相談員の異動・退職
- 担当変更の申し出
- 「引き継ぎ資料を作りたい」

---

## 実行手順

### ステップ1：引き継ぎサマリーの生成

対象の本人（仮名 `displayCode`）の包括的な引き継ぎ資料を生成する。

→ `neo4j-support-db` スキルの照会 2〜7（禁忌・推奨ケア・特性と願い・支える人・関わる機関と後見・手帳と受給者証）を `nest-personal` の `read_personal_cypher` で流す。0 件は照会 9（確認の状況）で「確認済み（0 件）」か「未確認」を分ける。

### ステップ2：支援記録の要約

過去の支援記録から重要なパターンを抽出する。

→ `neo4j-support-db` スキルの照会 10（支援記録）と照会 11（効果のあったケア）を流す。推移を数字で見るときは `insight-agent`。

**要約に含めるべきポイント:**
- 効果的だった対応トップ3
- 逆効果だった対応（禁忌として共有）
- 最近の変化・傾向
- 未解決の課題

### ステップ3：引き継ぎ資料の構成

以下の順序で資料を構成する（新担当者の安全を最優先）。

```markdown
# 引き継ぎ資料：C-……
作成日: [日付]
前任者: [職員の ID]

## 1. ⚠️ 最初に読んでください（安全情報）
- 禁忌事項一覧
- 避けるべき関わり方
- 経済的リスク

## 2. ✅ 効果的な関わり方
- 実証済みの対応パターン
- 好きなこと・落ち着くもの

## 3. 📋 基本情報
- 特性（氏名・生年月日・連絡先は Claude から出せない。手元の台帳で確かめる）
- 生育歴の要約
- 本人の願い

## 4. 🔗 支援体制
- キーパーソン（人の ID と続柄。優先順位付き）
- 利用中のサービス・事業所（機関の名前は資源の側で引く）
- 連携機関

## 5. 📅 期限管理
- 手帳・受給者証の更新日
- 次回モニタリング予定

## 6. 🔄 親の機能と代替体制
- 親が担うタスク（CareRole）
- 各タスクの代替手段
- バックアップの欠損

## 7. 📝 最近の支援状況
- 直近の支援記録要約
- 進行中の課題
- 申し送り事項
```

### ステップ4：エコマップの生成（オプション）

視覚的な支援関係図を引き継ぎ資料に添付する場合、ecomap-generatorスキルを使用。

テンプレート: `handover`（引き継ぎ用）を指定する。

### ステップ5：更新期限の確認

引き継ぎ時に期限切れ・期限間近の証明書がないか確認する。

→ `neo4j-support-db` スキルの照会 7（手帳・受給者証・年金と手当）を流す。全員の期限を見るときは照会 8。

期限切れが発見された場合は、引き継ぎ資料の冒頭に赤字で警告を追加する。

## マニフェストの「継続性（Continuity）」の実現

このプロトコルは、マニフェスト第3の価値「継続性」を直接実現するものである。

- **暗黙知の形式知化:** 前任者の頭の中にあった「あの人にはこう接すると良い」を、禁忌（NgAction）・推奨ケア（CarePreference）・支援記録（SupportLog）として、根拠の記録（Record）と一緒に蓄積する。登録は `narrative-extractor` の案を職員がゲートで通す
- **断絶の防止:** 担当者が変わっても、データベースに蓄積された知識がケアの質を維持する
- **コンテキストの継承:** 単なるデータの引き継ぎではなく、「なぜそうなのか」の文脈も含めて伝える

---

## 複数クライアントの一括引き継ぎ

担当者が複数のクライアントを引き継ぐ場合：

1. `neo4j-support-db` スキルの照会 1（本人の一覧）で、仮名の一覧を取得
2. 各クライアントについて上記手順を実行
3. 緊急度（禁忌の多さ、更新期限の近さ）でソートして優先順位をつける。未確定（照会 13）は「未確定」と添える
4. PDF/Excelでの一括出力が必要な場合は `html-to-pdf` スキルまたは `xlsx` スキルを使用
