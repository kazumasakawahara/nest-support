## 1. 二つのファイルと置き場所

| ファイル | 中身 | 書く人 |
|---|---|---|
| `~/.config/nest/external-api-record.json` | 契約の確認の記録（行ごと） | 契約を確かめた人 |
| `~/.config/nest/external-api-features.json` | 機能ごとの明示の設定（行ごとに `true` / `false`） | 使うと決めた人 |

- 記録と設定を分けたのは、記録を書いた人が同じ操作でそのまま有効にしてしまわないためです（台帳 G-23）
- 置き場所はコードに固定されています。環境変数では変えられません
- 二つとも、権限 600・持ち主が今の利用者・シンボリックリンクでないこと。一つでも外れたら、その行は止まります

```bash
mkdir -p ~/.config/nest && chmod 700 ~/.config/nest
# 下の例を写して書き、保存したら
chmod 600 ~/.config/nest/external-api-record.json ~/.config/nest/external-api-features.json
```

## 2. 契約の確認の記録の書式

最上位は `{"version": 1, "destinations": {…}}` です。**記録は NEXT の行ごとに分けて書きます。** ある行の記録で、別の行は開きません（Gemini の記録があっても Claude の行は開きません）。

下の例は NEXT-03（Gemini の文字起こし）です。〈…〉は書きかけの印です。日付も書きかけ（`YYYY-MM-DD`）のままなので、この例を写しただけでは通りません。

```json
{
  "version": 1,
  "destinations": {
    "NEXT-03": {
      "checkedBy": "〈確かめた人〉",
      "checkedOn": "YYYY-MM-DD",
      "contractName": "〈送り先と契約の名前〉",
      "contractVersion": "〈契約の版・日付〉",
      "trainingUse": "〈入力を学習に使うか〉",
      "retention": "〈保存の期間〉",
      "legalArrangement": "〈第 28 条の提供か、第 27 条第 5 項第 1 号の委託か、の整理〉",
      "sendsSensitiveData": true,
      "nextReviewOn": "YYYY-MM-DD"
    }
  }
}
```

| 鍵 | 記録の項目（`docs/external-api.md` §0） | 値の決まり |
|---|---|---|
| `checkedBy`・`checkedOn` | 確かめた人と日付 | 文字列・YYYY-MM-DD（今日より後は止まる） |
| `contractName`・`contractVersion` | 送り先と契約の名前・版 | 文字列（空は止まる） |
| `trainingUse`・`retention` | 入力を学習に使うか、保存の期間 | 文字列（空は止まる） |
| `legalArrangement` | 外国にある第三者への提供か、委託か、の整理 | 文字列（空は止まる） |
| `sendsSensitiveData` | 要配慮個人情報を送ること | 明示の `true` だけ（`"true"` や省略は止まる） |
| `nextReviewOn` | 次に確かめる日 | YYYY-MM-DD（過ぎたら止まる） |

- 鍵が一つでも欠けるか、決まっていない鍵があれば、その行は止まります
- **次に確かめる日**（`nextReviewOn`）：契約の版が変わったのに記録が古いまま残らないように置きます。その日を過ぎると行は止まります。止まったら契約を確かめ直し、`checkedOn` と `nextReviewOn` を書き直します。何日先にするかは、契約を確かめた人が決めます

## 3. 機能の設定の書式

```json
{
  "NEXT-03": true,
  "NEXT-04": false
}
```

- 行ごとに、明示の `true` だけが「有効」です。書いていない行と `false` は止まります
- 一覧に無い行（`NEXT-99` など）や、`true` / `false` でない値があると、どの行も止まります

## 4. doctor で確かめる

```bash
./scripts/doctor.sh
```

- [3] 接続の設定のファイル：二つのファイルが 600 で、リンクでないこと。無ければ WARN、権限が広いかリンクなら FAIL
- doctor はファイルの中身を読みません。中身は次の 5 で確かめます

## 5. その行が通ることを確かめる

ファイルを置いた後、開きたい行ごとに流します（例は NEXT-03）。

```bash
uv run python -c "from nest import egress; egress.authorize('NEXT-03'); print('NEXT-03：通る')"
```

- 通れば `NEXT-03：通る` と出ます
- 止まれば `EgressDenied` と理由（「記録に項目が欠けている」「次に確かめる日を過ぎている」など）が出ます。理由のとおり直して流し直します
- 開くつもりの無い行が止まることも確かめます：

```bash
uv run python -c "from nest import egress; egress.authorize('NEXT-01')"    # EgressDenied が出るのが正しい（台帳 G-80）
```

## 6. やめるとき

- 機能の設定で、その行を `false` にします。記録は残してかまいません（設定が `false` なら送りません）
- 契約が終わったら、その行の記録を消します
