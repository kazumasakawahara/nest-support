# ADR-001 nest-support の DB の作り直しと、四つの約束

- 状態：**草案**（2026-11-05。河原さんの承認待ち。D1 は河原さんの回答待ち）
- 日付：2026-11-05
- 関連：tsunagu-net ADR-008 D9、`~/Dev-Work/tsunagu-net/docs/contracts/nest-support-shared.md`（v1。以下「約束」）
- 前提の記録：止まる点 1 の報告（2026-11-05）と河原さんの返答（同日）。台帳は `docs/gray-decisions.md`

まず「未決論点」を読む。

## 背景

- nest-support は、主に相談支援専門員が、家族などの語りの TEXT や自分で作る面談記録などのケース記録を取り込む DB。親なき後の支援が目的で、中心は本人一人（ADR-008 D9）
- tsunagu-net とは別の DB にし、約束の四つ（資源 DB は同じものを使う・機関は資源 DB の機関 ID で指す・確度の言葉をそろえる・原文に無いことを補わない点検）だけをそろえる
- 今の雛形は約束と次の点で食い違う（止まる点 1 の表 3）
  - 機関（Hospital・Organization・ServiceProvider）を DB の中に持ち、名前の一致で決めている（約束 2）
  - 確度の項目が無い（約束 3）
  - Guardian Layer（`lib/schema_validator.py`）が型に合わないものを自動で直す。riskLevel の「高」を LifeThreatening に読み替えるなど、AI の値を上げる補正もある（約束 4-3・4-4）
  - Claude が MCP の `execute_query` で直接書く。AI 由来を未確定で入れる仕組みがテンプレートに無い（約束 4-5）
  - Client・KeyPerson・Supporter・Doctor を名前で MERGE し、AI に同一人物を決めさせている（約束 4-6）
  - 個人に紐づく文を Gemini で埋め込みにしている（河原さんの全体の方針と食い違う）
- nest-support の DB は今は無い扱い。ただし、前の DB の跡（コンテナ `nest-support-neo4j`・`neo4j_data/`・`neo4j_backup/`）が残っているので、実データが入っているものとして触らない（2026-11-05 河原さん。未決論点 9）

## 決定

**D1 正典の置き場：保留（河原さんの回答待ち）**

今のスキーマの正典は `~/Dev-Work/shared-schema/SCHEMA_CONVENTION.md` で、nest-support の `docs/SCHEMA_CONVENTION.md` はその写し。shared-schema は neo4j-agno-agent と oyagami にも効いている。

- 案 a（neo4j-agno-agent を使っていないなら推す）：nest-support の正典を nest-support の中に持つ（`docs/SCHEMA.md` と機械が読む JSON）。shared-schema の写しはやめる。約束の写しは持たず、版を記録して参照する
- 案 b：shared-schema に残し、v4 として作り直す。neo4j-agno-agent と oyagami にも同じ変更が及ぶ

河原さんの答え（neo4j-agno-agent を今も使っているか）を受けて決める。

**D2 資源 DB：配布の一式の書き出しを、nest-support 用の Neo4j に読み込み、読み取りだけで使う（河原さんの推す案）**

- tsunagu-net の配布の一式に入っている資源 DB の書き出しを、nest-support 用の Neo4j（今の compose のポート 7475・7688。tsunagu-net のポートは使わない）に読み込む
- 読み込んだ資源のノードは、読み込みの道具のほかは書かない。ゲートは資源のラベルへの書き込みを拒否する。読み込み直すときは、資源のノードを丸ごと置き換える
- 読み込んだ版（例：v0.29）と書き出しの指紋（`MANIFEST.json`）を DB の中に 1 件だけ記録し、照会の結果に添えられるようにする
- 機関の誤り・足りない機関は nest-support の中で直さず、tsunagu-net の手入力の表の手順に回す（約束 1）
- 今の共有層（neo4j-agno-agent の support-db-neo4j、7687）は nest-support から使わない。`provider-search` と `wamnet-provider-sync` は nest-support のスキルから外す

採用理由：ケースの事実と機関を一つの照会で結べる（Neo4j Community は DB をまたいで照会できない）。tsunagu-net の MCP を通す案より、使う人の手元で動くものが少ない。

却下した選択肢：

- **tsunagu-net の資源 DB の MCP（`tsunagu/mcp_resource.py`）を通す**：tsunagu-net の Neo4j も起動しておく必要がある。ケースの事実と機関を一つの照会で結べない
- **今の共有層（7687）を使い続ける**：tsunagu-net の資源 DB と別物で、約束 1 に反する。nest-support から書き込んでもいる

**D3 機関：資源 DB の機関 ID（`ORG-` ＋ ULID）を、個人の側のプロパティとして持つ**

- 病院・事業所・行政の窓口・法人の後見人などは、個人の側に `orgId` だけを持つ（例：通院の事実に、通院先の `orgId`）。名前・住所・電話・窓口は写さず、資源のノードから引く
- 個人の側から資源のノードへ関係（リレーション）を張らない。資源 DB を読み込み直しても、個人の側が壊れないようにするため
- 機関は名前の一致で決めない。取り込みでは機関の候補を出し、人が資源 DB で ID を選ぶ。選ぶまでは「機関未確定」として持つ（原文の名前は引用に残る）
- 資源 DB に無いもの（個人の医師、私的なつながり、資源 DB に無い機関）は、nest-support の中で持つ。ID の形は `ORG-` にしない
- 今のラベルのうち、Hospital・Organization・ServiceProvider・ProviderFeedback を個人の側から外す。Doctor は「資源 DB に無い個人の医師」として残す

却下した選択肢：

- **資源のノードへ関係を直接張る**：資源 DB を読み込み直すと関係が消えるか、資源の側を書き換えることになる（約束 1 の「読むだけ」に反する）
- **機関の名前と電話を個人の側にも写す**：約束 2 に反する。名前が変わった機関で食い違う

**D4 確度：事実ごとに五つの値の一つを持ち、作った後は変えない**

- 値は約束 3 のとおり：`Confirmed`・`Hearsay`・`SelfReport`・`Inference`・`Unspecified`
- 作った後は上げも下げもしない。確かめ直したら確認の記録（今の Review と CONFIRMS の形）を新しく作り、元の事実とつなぐ
- 確度と情報源は別の項目にする。情報源は今の `source`（本人・母親・父親・…・記録のみ）を使い、確度には混ぜない
- 他の機関から受けた書面の事実は、確度を二段で持つ：提供元の印による確度と、受けた側から見た確度（伝聞。提供元が推測・記載なしならそれと同じ）
- 家族の語りの多くは伝聞か本人の話。確認済みにしない
- `lastConfirmedAt` は事実の上に書き足さず、確認の記録から計算する（事実のノードを書き換えないため）

**D5 書き込み：Claude は案を作るだけ。ゲートが点検して未確定で入れ、人が承認して確定する**

- Claude は語り・記録を事実一つずつに分け、原文の該当箇所（引用）・確度・情報源をつけた「書き込みの案」（JSON）を出す
- 案は手元の Python のゲートが点検する（D6）。通れば `status: Pending`（未確定）で書き、AuditLog を残す。通らなければ書かずに理由を返す
- 人が案を見て承認したら確定（Active）にする。承認も AuditLog に残す
- Claude は直接書かない。MCP は読み取りだけにする（手段は未決論点 6）
- narrative-extractor の Cypher テンプレート（MERGE・ON MATCH SET による上書き）はやめる。既にある事実と食い違う情報は上書きせず、CONTRADICTS で保留する（今の正典 v3.4 の考え方を残す）

**D6 点検：約束 4 の六つを機械で行い、自動で直さない**

- ゲートは次を AI を使わずに点検する：引用が原文にあるか／引用に無い数字を足していないか／確度が原文の印と合うか（重なったら弱いほう。印が無ければ記載なし）／型に無い項目・値が無いか／AI 由来が未確定か／人を名前で同定していないか
- Guardian Layer の自動補正（camelCase への変換、旧い関係名の置き換え、riskLevel の別名の読み替え）はやめ、止めて理由を返す。直してよいのは、tsunagu-net と同じく、大文字・小文字の違いと確度の日本語名（確認済み・伝聞・本人の話・推測・確度の記載なし）だけにする
- EXTRACTION_PROMPT の「感情が明確でなければ Neutral」のような、原文に無い値で埋める指示は消す。分からない値は空のままにする
- tsunagu-net の試験 `tests/test_intake.py` の例（検出すべき入力と通すべき入力の両方）を nest-support の試験に写し、同じ結果になることを確かめる。写すのは架空の例だけ
- 原文の印の読み方（【確認済み】【伝聞】【本人の話】【推測】など）は tsunagu-net と同じにする

**D7 人の同定：名前で決めない**

- 本人（Client）・キーパーソン・支援者・家族は、ゲートが発番する ID で指す。`Client.name` の一意制約と、名前による MERGE をやめる
- 取り込みで名前が一致・似ている人は「候補」として出し、同じ人かは人が決める
- narrative-extractor の「健太・けんた・山田健太・山田くんを一つにまとめる」という指示は消す

**D8 埋め込み：やめる（2026-11-05 河原さん決定）**

- 個人に紐づく情報（支援記録・禁忌・ケアの好み・本人の要約・面談の音声と書き起こし）を埋め込みにしない。ベクトル索引（6 本）を作らない
- `lib/embedding.py` の埋め込み・意味検索・似た本人の検索、`scripts/backfill_embeddings.py`、登録時に埋め込みを付ける処理を外す
- 照会は構造クエリで行う
- 失う機能：支援記録・禁忌・面談の意味検索、似た本人を探す機能、意味の近い禁忌の重複検出

却下した選択肢：

- **公開情報だけ埋め込みにする**：DB の中には公開情報がほぼ無い（資源 DB は tsunagu-net の側にある）。手順書の検索は DB の外の道具で足りる
- **残す**：河原さんの全体の方針に反する。displayCode に置き換えても、障害名・禁忌・ケアの組み合わせで本人が分かる

**D9 外に送るもの：既定は「送らない」。送るものは使う前に文書に書く**

送り先ごとに、何を送るかを `docs/external-api.md`（新しく作る）に書く。使う前に書く。

*9-1 Google（Gemini）：文字起こし・手書きの OCR・構造化は、既定で止める（2026-11-05 河原さん）*

- 今は `GEMINI_API_KEY` があれば自動で送る。鍵は他のプロジェクトのために設定されていることもあるので、鍵の有無を「送ってよい」の印にしない
- 文字起こしと OCR は、機能ごとの明示の設定と、使う人が契約を確かめた記録（9-2 の案 B と同じ欄）の両方がそろったときだけ動く。そろわなければ、送らずに止めて理由を出す
- `scripts/multi_importer.py` の Gemini による構造化はやめる。構造化は Claude の書き込みの案とゲートの経路（D5）だけにする

*9-2 Anthropic（Claude）：語り・添付・MCP の照会結果*

今は、貼り付けた語りと添付のファイル、MCP の照会結果（実名・電話・生年月日を含む）がそのまま Claude に届く。MCP の経路には仮名化が効かない。

- 案 A「Claude には仮名だけ」：実名・連絡先・生年月日・住所を本人の事実から分けて持ち（今の正典の Identity の考え方）、MCP の読み取りの道具は仮名（displayCode）と事実だけを返す。実名との対応は手元の道具だけが持つ。語りは、取り込む前に手元で名前を仮名に置き換える
  - 限り：語りの置き換え漏れは機械で完全には防げない。出来事の中身で本人が分かることがある。仮名にしても、対応表を持つ事業所にとっては、他の情報と容易に照合して特定の個人を識別できる情報のままである（個人情報の保護に関する法律 第2条第1項第1号の括弧書き。e-Gov で照合済み 2026-11-05）
  - 失うもの：Claude が本人の名前で答えられなくなる（訪問準備の文書などは、手元の道具で実名に戻す工程が要る）
- 案 B「使う人が契約を確かめて記録する」：使う人（事業所）が、Anthropic との契約の条件（入力を学習に使うか、保存の期間、外国にある第三者への提供（同法 第28条）として扱うか、委託（同法 第27条第5項第1号）として扱えるか）を確かめ、雛形の記録の欄に書く。記録が無ければ、道具は実データの扱いに入らない
  - 限り：委託と提供のどちらに当たるかの判断は、使う人の契約と個人情報保護委員会の解釈による。私（Claude）は委員会の Q&A をまだ照合していない【未照合】
- **推す案：B を必ず行い、A のうち DB の側の部分（MCP が既定で実名・連絡先を返さない）を合わせる**。理由：nest-support の入力の中心は家族の語りで、語りを Claude に渡す以上、A だけでは送らないことにならない。それでも、照会の結果まで実名を流す必要は無い。語りの仮名への置き換え（A の後半）は、道具の重さを見て未決とする（未決論点 7）
- 要配慮個人情報（同法 第2条第3項。病歴などを含む。照合済み）が中心なので、契約の確認の欄には、要配慮個人情報を送ることを明記する

*9-3 LINE：SOS の通知*

今は、本人の名前・時刻・GPS の位置（地図のリンク）・キーパーソン上位 3 名の名前・続柄・電話・禁忌を LINE に送っている。`docs/PRIVACY_GUIDELINES.md` の「名前と緊急レベルだけ」は実態と違う（直す）。

- 案 a：LINE には「SOS があったこと・誰のことか（仮名か、同意を得た呼び名）・位置・確かめる先」だけを送る。電話と禁忌は、認証のある SOS の画面で見せる
- 案 b：中身は今のままで、本人・家族の同意と、使う人が LINE の契約を確かめた記録をそろえたときだけ送る
- 案 c：LINE をやめる
- 推す案：a。駆けつける人が電話と禁忌を見られないと困るので、SOS の画面を外から開けるかどうか（今の sos は手元の FastAPI）を先に確かめる（未決論点 8）
- 緊急時の提供は、同法 第27条第1項第2号（人の生命、身体又は財産の保護のために必要がある場合であって、本人の同意を得ることが困難であるとき。照合済み）に当たる場面がある。ただし、平時に LINE の事業者のサーバを通ることをどう扱うかは、9-2 と同じ判断が要る

## 撤退線

- **W1**：資源 DB の書き出しに、nest-support に要る機関（個人の医院など）が足りず、「機関未確定」が多くなりすぎたら、約束 1・2 を tsunagu-net と一緒に見直す（片方だけで変えない）
- **W2**：一人で使う相談支援専門員にとって承認の手間が重すぎたら、承認の単位（事実ごと・語りごと）を見直す
- **W3**：構造クエリだけでは探す仕事に足りないとはっきりしたら、外に送らない埋め込み（手元で動くもの）を別の ADR で検討する。外部の埋め込みには戻さない
- **W4**：仮名だけの照会が業務の取り違えを生むなら、9-2 の A の範囲を見直す

## 未決論点

1. **D1 の正典の置き場**：neo4j-agno-agent を今も使っているか（河原さんから回答）
2. **事実の単位**：同じ禁忌を別の日に別の人から聞いたとき、事実を一つにまとめるか、聞いた記録ごとに持って人がつなぐか（確度を変えない約束と、緊急時に一覧で見せたいことの両立）
3. **一人で使うときの承認**：tsunagu-net は「自分が登録したものは自分で承認できない」（G-35）。nest-support は相談支援専門員が一人で使うことが多い。自分で承認してよいか、してよいなら何を残すか
4. **事業所の口コミ（ProviderFeedback）の置き場**：個人の側にも資源 DB にも置かないなら、どこに置くか、やめるか
5. **資源 DB の書き出しの形と版の記録**：`scripts/make_distribution.py` と `MANIFEST.json` をまだ読んでいない。実装計画の前に読む
6. **MCP を読み取りだけにする手段**：Neo4j Community で読み取りの利用者を分けられるか、MCP の側の設定で足りるか。tsunagu-net G-14（読み取りモードはアクセス制御にならない）を確かめてから決める（Context7 で確かめる）
7. **語りを仮名に置き換えてから Claude に渡すか**（9-2 の A の後半）
8. **SOS の中身**（9-3）と、SOS の画面を外から開ける形にできるか
9. **残っている前の DB の跡**：`neo4j_data/`・`neo4j_backup/`・コンテナ `nest-support-neo4j` をどうするか（河原さん）。今は消さない・開かない・起動しない
10. **全文索引**：手元で動くので外には送らないが、本文を索引に載せるか。tsunagu-net は作らない側に倒した（G-9）。nest-support も作らない側から始めるか
11. **感情（emotion）・きっかけ（triggerTag）**：原文に書いていない AI の読み取りなら確度は推測になる。insight-agent の予兆検知はこれに頼っている。残すか、原文にあるときだけにするか
12. **field-ui と sos**：作り直すか、いったん外すか
13. **PRIVACY_GUIDELINES の条番号**：今の文書にある「個人情報保護法第20条第2項」は照合していない【未照合】。書き直すときに e-Gov で照合する

## 実装の順（計画の行は、この ADR の承認の後に `docs/implementation-plan.md` に書く）

1. 正典（D1 の答えに従う）と、機械が読む JSON・乖離の検査
2. ゲート：約束 4 の点検と、tsunagu-net の試験の例（両方向）
3. Guardian Layer の自動補正を外し、ゲートに置き換える
4. 埋め込みを外す（D8）。Gemini の送信を既定で止める（9-1）
5. 書き込みの経路と承認（D5）。MCP を読み取りだけにする
6. 資源 DB の読み込みの道具（D2）と、機関の候補の出し方（D3）
7. narrative-extractor と EXTRACTION_PROMPT の書き直し
8. 外部送信の文書（`docs/external-api.md`）と PRIVACY_GUIDELINES の書き直し
