# ADR-001 nest-support の DB の作り直しと、四つの約束

- 状態：**承認**（2026-11-05 河原さん。D1〜D11。D2-2 は同日の 2 回目の返答で承認。D3 は同日の止まる点 2 で改めた）
- 日付：2026-11-05（草案）、2026-11-05（承認版）
- 関連：tsunagu-net ADR-008 D9、約束 `~/Dev-Work/tsunagu-net/docs/contracts/nest-support-shared.md`（v1 確定。以下「約束」）
- 前提の記録：止まる点 1 の報告と河原さんの返答（2026-11-05 の 2 回）。承認なしに決めたことは `docs/gray-decisions.md`

まず「未決論点」を読む。

## 背景

- nest-support は、主に相談支援専門員が、家族などの語りの TEXT や自分で作る面談記録などのケース記録を取り込む DB。親なき後の支援が目的で、中心は本人一人（ADR-008 D9）
- tsunagu-net とは別の DB にし、約束の四つ（資源 DB は同じものを使う・機関は資源 DB の機関 ID で指す・確度の言葉をそろえる・原文に無いことを補わない点検）だけをそろえる
- 今の雛形は約束と次の点で食い違う
  - 機関（Hospital・Organization・ServiceProvider）を DB の中に持ち、名前の一致で決めている（約束 2）
  - 確度の項目が無い（約束 3）
  - Guardian Layer（`lib/schema_validator.py`）が型に合わないものを自動で直す。riskLevel の「高」を LifeThreatening に読み替えるなど、AI の値を上げる補正もある（約束 4-3・4-4）
  - Claude が MCP の `execute_query` で直接書く。AI 由来を未確定で入れる仕組みがテンプレートに無い（約束 4-5）
  - Client・KeyPerson・Supporter・Doctor を名前で MERGE し、AI に同一人物を決めさせている（約束 4-6）
  - 個人に紐づく文を Gemini で埋め込みにしている（河原さんの全体の方針と食い違う）
- nest-support の DB は今は無い扱い。前の DB の跡は、実データが入っているものとして、河原さんが確かめるまで触らない（未決論点 6）

## 決定

**D1 正典は nest-support の中に持つ（2026-11-05 河原さん）**

- neo4j-agno-agent は使わない（2026-11-05 河原さん）
- nest-support の正典を `docs/SCHEMA.md`（構造）と、機械が読む JSON に置く。意味と規則の文書が要るなら、同じく nest-support の中に置く
- shared-schema（`~/Dev-Work/shared-schema`）からの写しの同期は切る。nest-support の `docs/SCHEMA_CONVENTION.md`・`docs/SEMANTIC_MODEL.md`（同期の写し）は、新しい正典ができた時点で外す（git の履歴に残る）
- shared-schema は消さず、読むだけの参照として残す。nest-support から shared-schema を書き換えない
- 四つの約束は写しを持たず、約束（v1）を参照し、版を記録する

却下した選択肢：

- **shared-schema に残し、v4 として作り直す**：shared-schema は oya-inai-db も縛っている。nest-support の作り直しが、oya-inai-db に及ぶ

**D2 資源 DB：配布の一式の書き出しを、nest-support 用の Neo4j に読み込み、読み取りだけで使う（2026-11-05 河原さん）**

- D2-1 tsunagu-net の配布の一式に入っている資源 DB の書き出しを読み込む。読み込んだ版（例：v0.29）と指紋（`MANIFEST.json`）を記録し、照会の結果に添えられるようにする
- D2-2 読み込み方（2026-11-05 河原さん承認：推す案。ポートは止まる点 3 で決める）：書き出しは `neo4j-admin` の dump（DB を丸ごと置き換える形）で、Neo4j Community が持てる通常の DB は一つだけ（Neo4j Operations Manual。Context7 で確認 2026-11-05）。dump を個人の DB にそのまま読み込むと、個人の側が消える。そこで推す案は次のとおり
  - **推す案：nest-support 用の資源の Neo4j を、個人の Neo4j とは別に立て、dump をそのまま読み込む**。読み取りだけで使う。ポートは今の 7474・7475・7687・7688 と tsunagu-net の 17474・17687・27474・27687 を避ける
  - 読み取りだけにする方法は、tsunagu-net の `tsunagu/mcp_resource.py` と同じ形にする。手本は tsunagu-net の枝 `claude/tender-dijkstra-xo3wwc` のコミット `d8e6e2d` の版に固定して読む（2026-11-05 河原さん）。**main には未収録。main に入ったら参照先を書き換える**
  - 持ち込むもの（手本のとおり）：EXPLAIN の種類が読み取り（r）でなければ拒否／種類が r でも計画に LOAD CSV があれば拒否／手続きの呼び出しは許可の一覧（`db.labels`・`db.relationshipTypes`・`db.propertyKeys`）だけ通す／計画が読めないときは閉じる側に倒す／返す行数の上限（500）と読み取りのトランザクション
  - 手本は資源 DB（公開情報）向け。個人の側の MCP（D6）は、**同じ形に、実名・かな・電話・住所・生年月日の伏せ字を足したもの**にする（2026-11-05 河原さん）
  - 個人の側は D3 のとおり `orgId` だけを持つので、二つの DB を一つの照会で結ぶ必要は無い。機関の名前などは、読む道具が `orgId` で資源の側から引く
  - 別の案：一時の Neo4j に dump を読み込み、資源のノードを個人の DB に写す道具を作る。一つの照会で結べるが、写しの正しさを別に検査する必要がある
- D2-3 資源の側は読み込みの道具のほかは書かない。機関の誤り・足りない機関は nest-support の中で直さず、tsunagu-net の手入力の表の手順に回す（約束 1）
- D2-4 neo4j-agno-agent の共有層（7687）は、nest-support の DB からは使わない。`provider-search` と `wamnet-provider-sync` も nest-support の DB からは使わない。ただし、スキルそのもの（`~/.claude/skills` のつながり）は消さない（2026-11-05 河原さん）

却下した選択肢：

- **tsunagu-net の資源 DB の MCP（`tsunagu/mcp_resource.py`）を通す**：tsunagu-net の Neo4j も起動しておく必要がある。nest-support だけを使う人の手元で動かない
- **今の共有層（7687）を使い続ける**：tsunagu-net の資源 DB とは別物で、約束 1 に反する

**D3 機関：資源 DB の機関 ID（`ORG-` ＋ ULID）を、個人の側のプロパティとして持つ**

- 病院・事業所・行政の窓口・法人の後見人などは、個人の側に `orgId` だけを持つ。名前・住所・電話・窓口は写さず、資源の側から引く
- 個人の側から資源のノードへ関係（リレーション）を張らない（D2-2 で DB が別になる。資源 DB を読み込み直しても個人の側が壊れない）
- 機関は名前の一致で決めない。取り込みでは機関の候補を出し、人が資源 DB で ID を選ぶ。選ぶまでは「機関未確定」として持つ（原文の名前は引用に残る）
- 資源 DB に無いもの（個人の医師、私的なつながり、資源 DB に無い機関）は、nest-support の中で持つ。ID の形は `ORG-` にしない
- 個人の側のラベルから Hospital・Organization・ServiceProvider・ProviderFeedback を外す。Doctor は「資源 DB に無い個人の医師」として残す（→ 2026-11-05 に改めた。下の「D3 の改め」）

却下した選択肢：

- **資源のノードへ関係を直接張る**：資源 DB を読み込み直すと関係が消えるか、資源の側を書き換えることになる
- **機関の名前と電話を個人の側にも写す**：約束 2 に反する。名前が変わった機関で食い違う

**D3 の改め（2026-11-05 河原さん。止まる点 2）**

- 改める箇所：上の「Doctor は『資源 DB に無い個人の医師』として残す」。**`Doctor` のラベルは外す。** 個人の医師は、本人の周りの人をまとめた `Person` に持ち、本人との関係は `RELATED_TO {kind: PrimaryDoctor}` で表す。医療機関そのものは `Involvement {kind: Medical}` と `orgId` で持つ（正典 v0.2 §4）
- 変えないこと：個人の側に機関のノードを置かない・`orgId` の値だけを持つ・名前の一致で機関を決めない・資源 DB に無いものは nest-support の中で持つ
- 理由：家族・キーパーソン・主治医・近隣・ヘルパーを一つの `Person` にまとめると、同じ人（キーパーソンでもある母など）が二つのノードにならない。名前で同定しない（D8）こととも合う。「個人の医師を個人の側で持つ」という D3 の目的は変わらない
- 読み替えで済ませず、ここに改めとして書く（2026-11-05 河原さんの条件）

**D4 確度：聞いた記録ごとに五つの値の一つを持ち、作った後は変えない**

- 値は約束 3 のとおり：`Confirmed`・`Hearsay`・`SelfReport`・`Inference`・`Unspecified`
- 確度を持つのは「聞いた記録」（D5 の根拠）。作った後は上げも下げもしない。確かめ直したら新しい記録を作り、元の記録とつなぐ
- 確度と情報源は別の項目にする。情報源（本人・母親・父親・…・記録のみ）は確度に混ぜない
- 他の機関から受けた書面の事実は、確度を二段で持つ：提供元の印による確度と、受けた側から見た確度（伝聞。提供元が推測・記載なしならそれと同じ。提供元より強くしない）
- 家族の語りの多くは伝聞か本人の話。確認済みにしない
- 「最後に確かめた日」は事実のノードに書き足さず、聞いた記録と確認の記録から計算する

**D5 禁忌：一つのノードにし、聞いた記録ごとに根拠としてつなぐ（2026-11-05 河原さん）**

- 禁忌（NgAction）は一つのノードにする。誰から・いつ・どの原文で聞いたかは「聞いた記録」として別に持ち、確度・情報源・原文の引用を記録の側に持たせ、禁忌に根拠としてつなぐ
- 新しく聞いた話を既にある禁忌に結ぶかは、人が決める。自動ではまとめない（似た文の自動の重複検出もしない）。結ばなければ、新しい禁忌（未確定）として入る
- 既にある禁忌と食い違う話は上書きせず、食い違いとして保留する（今の正典 v3.4 の CONTRADICTS の考え方を残す）
- ケアの好み（CarePreference）など、ほかのケアの暗黙知に同じ形を広げるかは、正典の案で示して決める（止まる点）
- ラベル・関係の名前は、正典の案で決める（止まる点）

**D6 書き込み：Claude は案を作るだけ。ゲートが点検して未確定で入れ、人が承認して確定する**

- Claude は語り・記録を事実一つずつに分け、原文の引用・確度・情報源をつけた「書き込みの案」（JSON）を出す
- 案は手元の Python のゲートが点検する（D7）。通れば未確定（`Pending`）で書き、AuditLog を残す。通らなければ書かずに理由を返す
- Claude は直接書かない。MCP は読み取りだけにする（tsunagu-net の T-11 と同じく、読み取り以外を実行前に拒否する包みを作る）
- narrative-extractor の Cypher テンプレート（MERGE と ON MATCH SET による上書き）はやめる

**D7 点検：約束 4 の六つを機械で行い、自動で直さない**

- ゲートは次を AI を使わずに点検する
  - 引用が原文にあるか
  - 引用に無い数字を足していないか
  - 確度が原文の印と合うか（重なったら弱いほう。印が無ければ記載なし）
  - 型に無い項目・値が無いか
  - AI 由来が未確定か
  - 人を名前で同定していないか
- Guardian Layer の自動補正（camelCase への変換、旧い関係名の置き換え、riskLevel の別名の読み替え）はやめ、止めて理由を返す。直してよいのは、tsunagu-net と同じく、大文字・小文字の違いと確度の日本語名（確認済み・伝聞・本人の話・推測・確度の記載なし）だけにする
- EXTRACTION_PROMPT の「感情が明確でなければ Neutral」のような、原文に無い値で埋める指示は消す。分からない値は空のままにする
- tsunagu-net の試験 `tests/test_intake.py` の例（検出すべき入力と通すべき入力の両方）を nest-support の試験に写し、同じ結果になることを確かめる。写すのは架空の例だけ
- 原文の印の読み方（【確認済み】【伝聞】【本人の話】【推測】など）は tsunagu-net と同じにする

**D8 人の同定：名前で決めない**

- 本人（Client）・キーパーソン・支援者・家族は、ゲートが発番する ID で指す。`Client.name` の一意制約と、名前による MERGE をやめる
- 取り込みで名前が一致・似ている人は「候補」として出し、同じ人かは人が決める
- narrative-extractor の「健太・けんた・山田健太・山田くんを一つにまとめる」という指示は消す

**D9 承認：一人で使う人の自己承認を認める。ただし、まとめて承認しない（2026-11-05 河原さん）**

- 一人で使う人は、自分が取り込んだものを自分で承認してよい（tsunagu-net の「自分で登録したものは自分で承認できない」（G-35）とは、ここで分かれる）
- 承認は書き込みとは別の操作にする（取り込みの流れの中で、続けて自動で承認しない）
- 承認の画面・出力では、事実ごとに原文の引用を並べて見せる
- AI 由来のものを、まとめて一括で承認しない。事実ごとに承認する
- 承認は監査ログ（AuditLog）に残す。誰が、いつ、どの事実を、自分の取り込みとして承認したかが分かるようにする

**D10 埋め込み：やめる（2026-11-05 河原さん）**

- 個人に紐づく情報（支援記録・禁忌・ケアの好み・本人の要約・面談の音声と書き起こし）を埋め込みにしない。ベクトル索引（6 本）を作らない
- `lib/embedding.py` の埋め込み・意味検索・似た本人の検索、`scripts/backfill_embeddings.py`、登録時に埋め込みを付ける処理を外す
- 照会は構造クエリで行う
- 失う機能：支援記録・禁忌・面談の意味検索、似た本人を探す機能、意味の近い禁忌の重複検出

却下した選択肢：

- **公開情報だけ埋め込みにする**：DB の中には公開情報がほぼ無い。手順書の検索は DB の外の道具で足りる
- **残す**：河原さんの全体の方針に反する。displayCode に置き換えても、障害名・禁忌・ケアの組み合わせで本人が分かる

**D11 外に送るもの：既定は「送らない」。送るものは使う前に文書に書く（2026-11-05 河原さん）**

送り先ごとに、何を送るかを `docs/external-api.md`（新しく作る）に書く。使う前に書く。

*11-1 Google（Gemini）：文字起こし・手書きの OCR・構造化は、既定で止める*

- 鍵（`GEMINI_API_KEY`）の有無を「送ってよい」の印にしない。鍵は他のプロジェクトのために設定されていることがある
- 文字起こしと OCR は、機能ごとの明示の設定と、使う人が契約を確かめた記録（11-2 の欄）の両方がそろったときだけ動く。そろわなければ、送らずに止めて理由を出す
- `scripts/multi_importer.py` の Gemini による構造化はやめる。構造化は D6 の経路だけにする

*11-2 Anthropic（Claude）：契約を確かめて記録することを必ず行い、照会の結果には実名を返さない*

- 使う人（事業所）が、Anthropic との契約の条件を確かめ、雛形の記録の欄に書く。確かめる点：入力を学習に使うか、保存の期間、外国にある第三者への提供（個人情報の保護に関する法律 第28条）として扱うか、委託（同法 第27条第5項第1号）として扱えるか。要配慮個人情報（同法 第2条第3項）を送ることも明記する。記録が無ければ、道具は実データの扱いに入らない
- MCP の読み取りの道具は、既定で実名・電話・住所・生年月日を返さず、仮名（displayCode）と事実を返す。実名との対応は手元の道具だけが持つ
- 限り：家族の語りそのものを Claude に渡すので、送らないことにはならない。仮名にしても、対応表を持つ事業所にとっては、他の情報と容易に照合して特定の個人を識別できる情報のままである（同法 第2条第1項第1号の括弧書き）
- 委託と提供のどちらに当たるかは、使う人の契約と個人情報保護委員会の解釈による。委員会の Q&A は照合していない【未照合】
- 条番号は e-Gov で照合済み（2026-11-05）：第2条第1項第1号・第3項、第27条第1項第2号・第5項第1号、第28条

*11-3 LINE：SOS には「SOS があったこと・誰のことか・位置・確かめる先」だけを送る（案 a）*

- 誰のことかは、仮名か、本人・家族の同意を得た呼び名で示す
- キーパーソンの電話と禁忌は LINE に送らず、認証のある SOS の画面で見せる
- 今の `docs/PRIVACY_GUIDELINES.md` の「名前と緊急レベルだけ」は実態と違うので直す
- 駆けつける人が電話と禁忌を見られるように、SOS の画面を外から開けるかどうかを先に確かめる（未決論点 4）
- 緊急時の提供は、同法 第27条第1項第2号（人の生命、身体又は財産の保護のために必要がある場合であって、本人の同意を得ることが困難であるとき）に当たる場面がある。ただし、平時に LINE の事業者のサーバを通ることの扱いは、11-2 と同じ判断が要る

## 撤退線

- **W1**：資源 DB の書き出しに、nest-support に要る機関（個人の医院など）が足りず、「機関未確定」が多くなりすぎたら、約束 1・2 を tsunagu-net と一緒に見直す（片方だけで変えない）
- **W2**：自己承認（D9）が形だけになり、引用を見ずに承認が続く様子が監査ログに出たら、承認の見せ方と単位を見直す
- **W3**：構造クエリだけでは探す仕事に足りないとはっきりしたら、外に送らない埋め込み（手元で動くもの）を別の ADR で検討する。外部の埋め込みには戻さない
- **W4**：仮名だけの照会（11-2）が業務の取り違えを生むなら、見せる範囲を見直す
- **W5**：資源の Neo4j を別に立てる案（D2-2）が、使う人の手元で重すぎたら、写す道具の案に替える
