# 2026-10-30〜31 の作業の総括：WAM NET の修正から Neo4j の 2 層化まで

作成: 2026-10-31（クラウドのセッション）。neo4j-agno-agent の `docs/SUMMARY_2026-10-31.md` と同じ内容の写し。
台帳と作業の記録は neo4j-agno-agent 側にある（`docs/DB_REGISTRY.md`、`docs/DB_INVENTORY_TASKS.md`・`docs/DB_SPLIT_TASKS.md`・
`docs/CONSOLIDATION_TASKS.md`・`WAM-NET/MAC_TASKS.md`）。このリポジトリ（nest-support）は**個人層**。

**出発点**は、WAM NET の事業所データを絞り込むコードの市区町村コード表が間違っている、という tsunagu-net での指摘だった。
そこから、Mac の Neo4j 全体を「実用に耐えるもの」に整理するところまで広がった。
方式は一貫して、コード修正・設計・文書はクラウドのセッション、DB 操作と Mac 固有の確認は Mac の Claude Code に指示書で渡す、という分担。
DB に書く前は必ず dry-run で件数を出し、河原さんの承認を得て、バックアップを取ってから実行した。

## 1. WAM NET の取得を正しくした

- **範囲の確定**。北九州市（市全体と 7 区）、行橋市、中間市、苅田町、みやこ町、遠賀郡 4 町の 16 件に決め（河原さん決定）、
  総務省コードの参照表 `WAM-NET/soumu_area_codes_reference.json` と照合試験 `WAM-NET/test_area_codes.py`（27 件）を付けた。
- **絞り込みの根本的な誤りを発見**。WAM NET の先頭列「都道府県コード又は市区町村コード」は所在地ではなく**指定権者**のコード。
  そのため旧版は久留米市 694 件・八女市 1 件を拾い、近郊 414 件を落としていた。「事業所住所（市区町村）」列で絞り込む形に直した。
  新版の件数は 202509 が 2166 件、202609 が 2315 件。
- **半年ごとの更新に対応**。公開済みの最新時点を自動で探す `--period auto`、新しい公開があるかだけを確かめる `--check`
  （終了コード 0 = 手元が最新、10 = 新しい公開あり）を付けた。毎月 1 日の launchd（`jp.lawnest.wamnet-check`）はこれを使う。
  legal-db にあった旧い月次書き込み処理（`com.kawahara.wamnet-supplement.plist`）は `launchctl unload` で止めた。

## 2. 共有層の DB を作り直した

- **取り込み（`sync_providers.py`）を 3 回の dry-run で練り直した**。ID の形が新旧で混在していたため、廃止の誤判定や二重登録を防ぐ照合
  （providerId → 事業所番号＋サービス種類 → 事業所番号のみ → 新規）を実装した。
- **重複 1257 組をまとめ（`merge_duplicate_providers.py`）、1708 ノードを削除**。
  ServiceProvider は 4213 → 4728（取り込み）→ 3020（まとめ）→ 3032（再取り込み）に収束。
  Closed 126、近郊外は `outOfArea` 印を付けて 601 件残した。新形式 providerId は 2445。
- **個人ノード 166 件を削除**（`scripts/purge_personal_nodes.py`）し、共有層は ServiceProvider だけ（リレーション 0）になった。
  イニシャルの実データ 1 件は nest-support 側に完全な形（NgAction つき）があることを確かめ、共有層側は消した。
- 試験は 61 件（取り込み 16、重複まとめ 18、コード表 27）。

## 3. Mac の Neo4j を 2 層に整理した

| 層 | DB | ポート | リポジトリ |
|---|---|---|---|
| 共有層（事業所・行政・制度） | support-db-neo4j | 7687 / 7474 | neo4j-agno-agent |
| 個人層（利用者・家族・支援記録） | nest-support-neo4j | 7688 / 7475 | nest-support |
| 独立した実験（民法総則） | law-graph-db | 7692 | legal-db（ローカル、git 管理外） |

- **閉じたもの**: oya-inai-db（UI の試作。文書 6 つは nest-support の `docs/archive/oya-inai-db/` に移してコンテナ・フォルダ削除）、
  livelihood-support（断念。7688 番を個人層に譲った）、旧試作 2 つ（neo4j-skillgraph・エコマップ用 neo4j-support-db）、
  Neo4j Desktop の練習用 2 つ（disability-support・Senior-Support。河原さんが削除）。
- **一本化**: 個人層のアプリとスキルは nest-support に集約。neo4j-agno-agent 側の api・frontend・lib・sos・mobile・個人層スキルなどは
  `archive/personal-layer-2026-10/` に退避し、CLAUDE.md・README・pyproject.toml を共有層のリポジトリとして書き直した。
  `~/.claude/skills/` の 13 本はすべて nest-support を向く（narrative-intake のリンクは外し、narrative-extractor に一本化）。
- **パスワード**: 公開リポジトリに初期パスワードが追跡されていたため、両層を別の値に変え、設定はすべて env ファイル
  （`~/.config/nest/neo4j.env`・`neo4j-personal.env`）から読む形にした（Windows のインストーラーも含む）。履歴は書き換えていない。
- **台帳** `docs/DB_REGISTRY.md` に、どの DB に何があり、どこで動き、誰が面倒を見るかを一枚にまとめた。
  バックアップは 5 時点（10/30 20:11、10/31 07:51・08:13・11:40・11:50）すべて `keep_` 付きで保全。

- law-graph-db は独立した実験として残す。共有層に入れる法令は、福祉関係の**条文層だけ**を e-Gov から新規に入れる（要件事実の層は入れない）。時期・設計は未定。
- `USES_SERVICE` は `wamnetId` で共有層の事業所を指す。Community 版は DB をまたげないので、事業所名は共有層にもう一度問い合わせる。
