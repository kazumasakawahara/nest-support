# 外部 API の一覧（何を送るか）

- 状態：v0.11（2026-11-06。N-00。河原さんが承認。方針は ADR-001 D10・D11）
- 根拠：ADR-001 D10（埋め込みをやめる）・D11（外に送るものは既定で送らない）、約束 v1.1「外部 API に何を送るか（それぞれが文書に書く）」
- **この一覧に無い送信はしない。** 行を足すか、「既定」を変えるときは、河原さんが決め、その人と日付を書く
- 「外部」とは、使う人の Mac の外にある、他者が運営するサービスのこと
- **受け手の端末が送るもの（リンクを開いたときなど）は、この一覧の外**とする。この一覧が扱うのは、nest-support の道具と、使う人の Claude が送るものだけ（2026-11-05 河原さん。台帳 G-18）
- 「使う人」とは、nest-support を使う相談支援専門員・事業所のこと

## 0. 前提

- **Claude に読ませた内容は、Anthropic の API に送られる。** 貼り付けた語り、添付のファイル、MCP の照会の結果のどれも同じ。「Mac で動かせば外に出ない」わけではない
- nest-support の DB（個人の側）の中身は、要配慮個人情報（個人情報の保護に関する法律 第2条第3項）を中心にする。既定ではどこにも送らない
- 外部 API の鍵（`GEMINI_API_KEY` など）が設定されていることを、「送ってよい」の印にしない。鍵は他のプロジェクトのために設定されていることがある（ADR-001 D11-1）
- **契約の確認の記録**：実データを送る行は、使う人が送り先との契約を確かめ、次の項目を記録したときだけ使える。記録は一つの JSON（`~/.config/nest/external-api-record.json`、権限 600）に、送り先（NEXT の行）ごとに書く。機械が確かめる条件は §5（2026-11-05 河原さん。台帳 G-19）
  - 確かめた人と日付
  - 送り先と契約の名前・版（例：どのプランの利用規約か）
  - 入力を学習に使うか、保存の期間
  - 外国にある第三者への提供（同法 第28条）として扱うか、委託（同法 第27条第5項第1号）として扱えるか、の整理
  - 要配慮個人情報を送ること
- 5 項目と、記録の JSON の項目の名前の対応（2026-11-05 河原さん承認。台帳 G-24）。人が読むこの表と、機械が確かめる名前（`nest/egress.py` の `RECORD_FIELDS`）がずれたら試験が失敗する

| §0 の項目 | JSON の項目の名前 | 値 |
|---|---|---|
| 確かめた人と日付 | `checkedBy`・`checkedOn` | 文字列・YYYY-MM-DD（今日より後は不許可） |
| 送り先と契約の名前・版 | `contractName`・`contractVersion` | 文字列 |
| 入力を学習に使うか、保存の期間 | `trainingUse`・`retention` | 文字列 |
| 外国にある第三者への提供か、委託か、の整理 | `legalArrangement` | 文字列 |
| 要配慮個人情報を送ること | `sendsSensitiveData` | 明示の `true` だけ |
| （次に確かめる日） | `nextReviewOn` | YYYY-MM-DD（過ぎたら不許可） |

- 記録の JSON の最上位は `{"version": 1, "destinations": {"NEXT-xx": {上の項目}}}`
- 条番号は e-Gov で照合済み（2026-11-05）。委託と提供の区別についての個人情報保護委員会の Q&A は照合していない【未照合】

## 5. 機械の歯止め（実装で入れる）

- 送り先の一覧（この文書の NEXT 行のホスト）をコードに持つ。一覧に無い送り先には送らず、失敗させる（N-02）
- Gemini と LINE は、機能ごとの明示の設定と契約の確認の記録がそろわなければ送らない。鍵の有無は見ない（N-02・N-03）
- **「記録」と「設定」は別のファイル**：契約の確認の記録は `~/.config/nest/external-api-record.json`、機能ごとの明示の設定は `~/.config/nest/external-api-features.json`（`{"NEXT-xx": true/false}`）。両方そろって初めて送る。記録を書いた人が、同じ操作でそのまま有効にもしてしまわないため。設定のファイルにも記録と同じ条件（権限 600・持ち主が今の利用者・シンボリックリンク不可・一覧に無い行や true/false でない値があれば不許可）をかけ、行ごとに明示の `true` だけを有効とする（2026-11-05 河原さん。台帳 G-23）
- 契約の確認の記録を機械が確かめる条件（2026-11-05 河原さん。台帳 G-19）。どれか一つでも満たさなければ「不許可」とし、閉じる側に倒す
  1. 記録は送り先（NEXT の行）ごとに持つ。ある行の記録で、別の行は開かない（Gemini の記録があっても Claude の行は開かない）
  2. 項目（§0 の 5 項目）がすべて埋まっている。欠けている項目は「無い」ではなく「不許可」として扱う
  3. 「要配慮個人情報を送ること」は、明示の `true` だけを許す。既定値で通さない
  4. 「次に確かめる日」を持ち、過ぎていたら不許可（契約の版が変わったのに記録が古いまま残るのを防ぐ）
  5. ファイルが無い・読めない・権限が 600 より広い、のどれでも不許可
  6. 置き場所はコードに固定する。環境変数で差し替えられるようにしない（鍵の有無を印にしないのと同じ理由）
- MCP の読み取りの包みは、既定で実名・かな・電話・住所・生年月日を返さない（N-22）
- 個人の側の包みは、NEXT-02 の設定と記録がそろうか、つないでいる DB に架空の印（`NestLiveProbe`）があるときだけ動く。どちらも無ければ拒否する（2026-11-06 河原さん。台帳 G-54 (3)）
- **資源の側の DB**：当面は nest-support 専用の写し（`nest-redesign-resource`、127.0.0.1:38687）を使う。本番で tsunagu-net の資源 DB につなぐ場合のポートは **17687（資源）**。**27687 は tsunagu-net のケース DB で、nest-support からは一切つながない**（2026-11-06 河原さん。台帳 G-50）
