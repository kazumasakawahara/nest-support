- 版：2026-11-06（計画 N-29。ADR-001 の作り直しに合わせて書き直した）
- 外に何を送るかの正は `docs/external-api.md`。この文書はその要約と、事業所の運用で決めることの一覧
- 条番号は e-Gov 法令検索で照合したものだけを書く。照合できないものは【未照合】と書く

## 1. はじめに

nest-support は、知的障害・精神障害のある方の支援の情報を扱います。障害があること、病歴、医療の情報、生活の歴史は**要配慮個人情報**です（個人情報の保護に関する法律 第 2 条第 3 項、同法施行令 第 2 条第 1 号。2026-11-06 e-Gov で照合）。

この文書は、nest-support を使う事業所が個人情報保護の規程を整えるときの参考です。各事業所の規程と照らし合わせて使ってください。

---

## 2. データの置き場所と流れ

### 2.1 置き場所

| もの | 置き場所 | 中身 |
|---|---|---|
| 個人の側の DB | 使う人の Mac の Docker（`127.0.0.1` だけで待ち受ける） | 本人・家族・支援の記録 |
| 資源の側の DB | 同上（別のコンテナ） | 事業所・窓口などの公開情報（tsunagu-net の写し。読むだけ） |
| 接続の設定（パスワード） | リポジトリの外（`~/.config/nest/` の設定のファイル） | リポジトリにも会話にも書かない |

- 書き込みはゲート（`nest/gate/`）だけが行います。ゲートはすべての書き込みに操作の記録（`AuditLog`）を付けます
- 支援の情報を埋め込み（ベクトル）にしません。似たものの検索の索引も作りません（ADR-001 D10）

### 2.2 Claude への送信（NEXT-01・NEXT-02）

Claude（Anthropic）に送られるのは、語りから書き込みの案を作るときの文と、DB の照会の結果です。

- 照会は読み取りだけの包み（MCP `nest-personal`）を通ります。包みは実名・かな・電話・住所・生年月日を返しません。本人は仮名（`displayCode`）で呼びます
- 原文の全体は返さず、根拠の引用は求められたときだけ 200 字までです
- **実データでは使いません。** 使う人が Anthropic との契約（データの扱い）を確かめ、その記録がそろったときだけ使えます（`docs/external-api.md` §5）

### 2.3 Google（Gemini）への送信（NEXT-03・NEXT-04）

面談の録音の文字起こしと手書きの記録の読み取り（OCR）は、**既定で止めています。** 機能ごとの明示の設定と、契約の確認の記録の両方がそろったときだけ動きます。埋め込みと文書の構造化（前の版にあった NEXT-06・NEXT-07）はやめました。

### 2.4 LINE への送信（SOS。NEXT-05）

**既定で使いません。** 使うときに送るのは、SOS があったこと、仮名（`displayCode`）、発信の時刻、位置（地図のリンク）、確かめる先（「手元の緊急連絡カードと SOS の画面」）だけです。電話・禁忌・実名は送りません。

- LINE のグループのメンバーを管理し、退職した人をすぐに外す

---

## 3. 仮名で呼ぶ運用

- Claude の中では、本人を仮名（`displayCode`。`C-` と 6 字）で呼びます。仮名は名前・生年月日・連番から作らず、ゲートが付けます
- 名前から仮名を引く入口は Claude の外（手元の画面か小さなコマンド）に置きます
- 禁忌（`NgAction`）と推奨ケア（`CarePreference`）の中身は伏せません。緊急のときに正しく読めることが本人の安全につながるためです
- 研修・説明会・開発では、架空の事例だけを使います。架空のものには「架空」の印を付けます

---

## 4. アクセスの管理

- Mac のログインのパスワード、離席するときの画面のロック、OS の利用者の分離
- DB のパスワードは、既定の値のまま使わない。設定のファイルはリポジトリの外に置く
- DB は `127.0.0.1` だけで待ち受けます。ほかのパソコンから接続できるように変えない

## 5. 保存・バックアップ・廃棄（事業所で決めること）

- **バックアップの手順と保管の場所**（2026-11-06 止まる点 F-1 で決めた。計画 N-33）：置き場所は `~/nest-backup/`（リポジトリの外。権限 700、Time Machine の対象外）。バックアップは要配慮個人情報の写しなので、外のサービスに置かない。DB に書き込んだ日の作業の終わりに、DB を止めてから `uv run python scripts/backup.py dump` で取る。世代は 4 つで、古いものは道具が消す。戻すときは DB を止めて `uv run python scripts/backup.py restore <世代>`。FileVault が有効であること、置き場所の権限と Time Machine の除外は `./scripts/doctor.sh` が確かめる
- **廃棄の手順**（2026-11-06 止まる点 F-1 で決めた。計画 N-32）：本人一人ずつ、Administrator が手元の道具 `scripts/purge_client.py` で消す。(1) Administrator がゲートで保存の判断（`RetentionDecision`。残す／消す、理由に名前を書かない）を書く。人の操作だけで、AI の案からは作れない (2) 試しの実行で、消す件数・残す人（ほかの本人にもつながる人）の数・他の機関から受け取った記録の件数を見る。他の機関から受け取った記録を消してよいかは人が確かめる。その本人の記録の原文の音声（`nest_voice_data/`）の件数も出る (3) 仮名を打ち返して消す。音声も同じ操作の中で消える。監査ログに `Purge` が 1 件だけ残る（件数だけ。名前・理由は残さない） (4) 新しいバックアップを取り、戻せることを確かめてから、消した日より前のバックアップを人が消す。保存の判断が無いか、最後の判断が「残す」なら、道具は試しの実行でも動かない。Claude は廃棄しない。限界：Neo4j は消した場所をすぐには上書きせず、トランザクションの記録も既定の期間は残る。守りは FileVault と古いバックアップを消すこと。いつ消すか（保存の期間）は事業所の記録の保存の規程による（法令の年数は【未照合】）
- **面談の音声ファイル**（2026-11-06 止まる点 F-1 で決めた。計画 N-37）：field-ui の録音は `nest_voice_data/`（権限 700、Time Machine の対象外）に置き、文字起こしの記録が承認されたら・遅くとも 30 日で `scripts/purge_voice.py` が消す。`documentHash` は残す。詳しくは `docs/VOICE_RECORDING_GUIDE.md` の「音声ファイルの置き場所と保存の期間」

## 6. 漏えいのおそれがあるとき

1. DB を止める（`docker compose --env-file <接続の設定のファイル> down`）
2. 操作の記録（`AuditLog`）で、誰が何をしたかを確かめる
3. 管理者と個人情報保護の責任者に報告する
4. 原因を確かめ、パスワードの変更・権限の見直しをする
5. 法令に基づく報告・本人への通知の要否を判断する（個人情報保護委員会への報告と本人への通知の条は【未照合】）

## 7. 法的な根拠

| 事項 | 条 |
|---|---|
| 要配慮個人情報の定義 | 個人情報の保護に関する法律 第 2 条第 3 項、同法施行令 第 2 条第 1 号（身体障害・知的障害・精神障害（発達障害を含む））（2026-11-06 e-Gov で照合） |
| 要配慮個人情報の取得には、あらかじめ本人の同意が要る（法令に基づく場合、生命・身体・財産の保護に必要で同意を得るのが難しい場合などの例外がある） | 同法 第 20 条第 2 項（2026-11-06 e-Gov で照合） |
| 個人データを第三者に提供するには、あらかじめ本人の同意が要る（法令に基づく場合、生命・身体・財産の保護に必要で同意を得るのが難しい場合、公衆衛生の向上・児童の健全な育成に特に必要で同意を得るのが難しい場合などの例外がある） | 同法 第 27 条第 1 項（2026-11-06 e-Gov で照合） |
| 障害福祉サービスの事業者の秘密の保持 | 【未照合】（指定基準の条。事業の種類ごとに違う） |
