## 2. 推す案（河原さんの考え 1〜5）

1. **範囲**：新しい人（AI 由来・未確定）と一緒に入る続柄だけ。既に確定している人・既にいる人に、後から続柄を足す道は今回作らない（§7 の残る論点）
2. **確定のしかた**：AI 由来の `RELATED_TO` は `Pending` で入る。その人を承認したときに一緒に `Active`、差し戻したときに一緒に `Inactive` になる。関係だけを承認・却下する操作は作らない。承認の画面に「この人は本人の〈続柄〉（根拠の引用）」を出す。人の承認は、続柄の根拠の記録が未確定なら止まる（2026-11-11 の決まりと同じ。根拠を一緒には承認しない）
3. **案に書ける値**：親族の 8 つ（`Parent`・`Child`・`Spouse`・`Partner`・`Sibling`・`Grandparent`・`Grandchild`・`OtherRelative`）と、`PrimaryDoctor`・`Neighbor`。`KeyPerson`・`Helper`・`OtherSupporter` は案に書けず、入口の点検が止める（判断や役割の評価を含むため。`KeyPerson` は職員が決める）
4. **書けるのは原文に続柄が書いてあるときだけ**。根拠は、その続柄が読める引用の記録（同じ案の事実）。確度は根拠の記録の確度を写し、それより強くしない
5. **新しい人を作る前に**、Claude は照会口で既にいる人の続柄を読む。同じ続柄の人がいれば「既にいる〈続柄〉の人（PER-…）として結びますか」と職員に尋ね、自分では決めない。同じ続柄でも別人のことがある（姉と兄はどちらも `Sibling`）ので、決めるのは人（D8・約束 4-6）

### 推す案の理由

- 関係には ID が無い（正典の `RELATED_TO` に ID の項目が無い）。関係だけを承認するには、関係を指す項目を正典に足すことになる。人と一緒に確定すれば、正典の構造（ラベル・関係・項目）は変わらない
- 範囲を「新しい人と同じ依頼の続柄」に限れば、未確定の人から張られた未確定の続柄は、必ずその人を作った依頼のものになる。承認のときに「どの続柄を一緒に変えるか」で迷わない
- 値を 10 に絞る：原文の語で読める続柄（親・姉・主治医・近所の人）は事実として写せる。`KeyPerson`（誰を鍵の人とみるか）・`Helper`・`OtherSupporter`（支え方の評価）は、原文の一語から決まらない

### 違う意見の併記（Claude）

- **値**：`PrimaryDoctor`・`Neighbor` を入れることに異論は無い。ただし `PrimaryDoctor` は、資源の側にある医療機関の医師なら `Involvement {kind: Medical}` と機関の側で持つ（SCHEMA §4.3）。案の段階では区別できないので、「個人の主治医として人を作る」ときだけ書ける、と SKILL に一言添えるのを推す
- **承認を止める根拠の範囲**：推す案は「続柄の根拠の記録（`evidenceRecordIds`）が未確定なら止める」。人が話した記録（`TOLD_BY` の元）が未確定でも、今は人の承認は止まらない。ここは今のまま（止めない）を推す。人そのものは「その人が話した」ことで足りており、話の中身の承認とは別だから
- **一緒に変える方向**：差し戻しで続柄も一緒に `Inactive` にすることに賛成。逆（人は承認するが続柄だけ差し戻したい）は、この案ではできない。そのときは人ごと差し戻し、続柄を書かずに案を出し直す。不便が出たら、関係に ID を足す案（正典の変更）を別に出す

## 5. 原文の続柄の語と値の対応を、入口でどこまで確かめるか

**案 A：語の一覧で確かめる（推す）**

- 値ごとに語の一覧を持ち、根拠の引用にその値の語が一つも無ければ止める。例：`Parent`＝母・父・お母さん・お父さん・母親・父親、`Sibling`＝姉・兄・妹・弟・きょうだい、`Grandparent`＝祖母・祖父・おばあさん・おじいさん、`Spouse`＝妻・夫、`Child`＝息子・娘・子、`PrimaryDoctor`＝主治医、`Neighbor`＝近所・隣
- 一覧に無い語（義姉・叔父・いとこなど）は止まる。止まっても人は `TOLD_BY` で入り、続柄を書かない案で出し直せる（安全な側に倒れる）。`OtherRelative` は語が広いので、一覧を短くして始め、止まった語を見て足す
- 置き場所は SEMANTICS（意味の文書）に表として置き、コードはそこから読む（表示名と同じ形）
- 理由：決まり 4「原文に続柄が書いてあるときだけ」を機械で確かめられる。承認する人の見落としに頼らない。約束 4 の「原文に無いことを補わない」に一番近い

**案 B：引用を必須にして、承認で人が見るだけ**

- 入口は「引用が案の事実のどれかである」ことだけを見る。語と値が合っているかは、承認の画面で人が引用を見て決める
- 一覧の手入れが要らない。そのかわり、「母が話した」を `Sibling` と書くような取り違えが、承認する人の目に頼る

**意見**：案 A を推す。ただし一覧は「止める理由」にだけ使い、一覧にあるから正しいとはしない（承認で人が見るのは案 B と同じ）。一つの引用に二人の続柄が出る文（「母が姉の話をした」）は、語があるので通ってしまう。これは承認で人が見る

## 7. 残る論点（今回は決めない）

- **既にいる人に後から続柄を足す道**：今回は作らない。実データを入れる前には要ると考える。作るなら、確認の記録（`Review`）と同じく職員が自分で作る道（Human 由来。未確定を経ない）にするのがよい。AI が既にいる人に続柄を足す形は、§3 の「新しい人からだけ」の決まりと分けて別に決める
- **C-N5AE5P の結ばれていない 3 人**（試走の DB。母・事業所の生活支援員・姉。どれも AI 由来・未確定で、続柄は 0 本）：上の道ができるまで結べない。試走の DB の中身なので、結ぶ道ができてから使うか、そのままにして新しい試走の本人で確かめるかを、そのときに決める
- 承認の画面で、続柄だけを差し戻したいときの扱い（§2 の違う意見の併記）
- `ChangeProposal`（ADR-002）と版の番号の順（§3）。2026-11-12 に決まった：この提案が v0.14、`ChangeProposal` は v0.15
