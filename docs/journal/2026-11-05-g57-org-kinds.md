# 2026-11-05 担当機関の推定で候補にする機関の種類（台帳 G-57 の (1)）

河原さんの依頼（2026-11-05）で、計画 N-24a の候補の種類 8 つ（`nest/org_estimate.py` の `CONSULTATION_KINDS`）の理由を出す。**まだ変えない。** tsunagu-net の側で照らしてから、河原さんが決める。

種類の値は tsunagu-net の正典の `orgKind`（SEMANTICS ENU-14、日本語名はスキーマ案 §3.3）の名前のまま。
「担当（SERVES）の数」は、2026-11-05 に読み込んだ資源の側（tsunagu-net の正典 v0.29 の書き出し）で、その種類の機関から地区（`Area`）へ張られた `SERVES` の数。

## 前提：住所から推定できるのは、地区の担当（SERVES）がある種類だけ

推定は「本人の住所の区 → その区（と上の市）を `SERVES` で担当する機関」で引く。資源の側で `SERVES` を持たない種類は、どれを選んでも候補に出ない。
`SERVES` を持たないのは、本人や家族が契約で選ぶ事業所（相談支援事業所・障害福祉サービス事業所・居宅介護支援事業所・介護サービス事業所）と、学校・保育所・市税事務所・児童福祉施設。これらは住所で決まらないので、名前から引く（計画 N-24 の `org_candidates.by_name`）。

## 年齢や障害の種類で、選ぶ種類を変えているか

**変えていない。** 種類 8 つは固定で（`CONSULTATION_KINDS`）、本人の年齢・障害の種類（`Condition`）・手帳の種類を見ていない。
候補の中から、語りの文脈でどれかを選ぶのは Claude（確度 `Inference`）で、確定は職員の承認。

その結果、次のことが起きる：
- 本人が子どものとき、子どもの窓口（こども家庭センター・児童相談所）が候補に出ない
- 本人が若い成人でも、高齢の窓口（高齢福祉課・地域包括支援センター・介護保険課）が候補に出る（親の介護の相談には当たるが、関わりは本人に結ぶ（`CONCERNS → Client`）ので、親についての関わりとして読まれるおそれがある）

## 見直しが要る点（私の見立て。決めるのは河原さん）

1. **`CareInsuranceDivision` は外すほうが筋が通る。** tsunagu-net の ENU-14（v0.21）は、この種類を「施設での高齢者虐待の対応、事業所への事実の確認・立入り・指導・勧告を受け持つ本庁の課」と定め、区の高齢の担当課（`ElderlyDivision`）と分けている。相談窓口ではないという点で、外した `DisabilityServiceSupervision` と同じ立ち位置になる
2. **`SocialWelfareCouncil` は入れる理由がある。** 日常生活自立支援事業（金銭管理の支援）は社会福祉協議会が担い、Pillar 6（金銭的安全）に直結する
3. **`GuardianshipCenter` は、後見そのもの（`Guardianship`）でなく、後見の相談（`Consultation`）としてなら候補にできる。** 外した理由（後見は推定で作らない）は関わりの種類の話で、機関の種類を外す理由にはならない
4. **年齢で分けるかどうか。** 本人が 18 歳未満のときだけ子どもの窓口を足す、などの分け方は、本人の生年月日を推定に使うことになる（今は住所の区だけを使っている）
