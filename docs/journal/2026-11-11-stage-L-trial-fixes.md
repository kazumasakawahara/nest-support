## L-2 の論点へ回したもの（6）

`docs/proposals/2026-11-08-stage-L-M.md` の段階 L に「L-2 で決める論点（2026-11-11 の確かめから）」として足した。

1. **差し戻した禁忌を新しい根拠で出し直すと、別の 1 件になる。** 差し戻した NgAction（NGA-…91386。Inactive）と同じ内容を新しい根拠で出し直すと、新しい NgAction が入り、承認後は同じ内容が Active と Inactive で二つになる。根拠も分かれる（母の話の記録は無効の方に結ばれたまま）。承認のときに前の根拠を新しい方に結び直す手段（または、出し直しを新規でなく「修正」として扱う形。L-1 の 5 種の一つ）をどうするか
2. **危険度が分からないときの値が無い。** `riskLevel` は 3 値（LifeThreatening・Panic・Discomfort）から選ぶしかない。今回は安全側で LifeThreatening にした。値を足すなら正典の変更（河原さんの承認）が要る
3. **関わりにサービスの種類を書く欄が案の形に無い。** 正典の `Involvement` には `serviceTypeName`（任意）がすでにあるが、入口の点検（`nest/gate/intake.py` の `INVOLVEMENT_KEYS`）が受けない。機関を候補から選ぶ操作で埋まる想定かを確かめた：**埋まらない。** 書き込み受付（`nest/gate/proposal.py`）は担当機関の推定の候補（estimate）を入口の点検に渡していないので、nest-gate 経由では関わりの `orgId` 自体が書けない（書くと「候補に無い」で止まる）。また候補は区域の窓口（区役所・成年後見センター）の推定で、サービスの事業所は候補に出ない。案の形に `serviceTypeName` を足すか（正典の変更は要らない）、事業所を選ぶ操作と合わせるかを決める

## 追記：河原さんの確認の後に直したこと（2026-11-11）

- **項目の表示名を足した。** SEMANTICS に「項目の表示名」（SEM-FIELD-01）を足し、show は項目を日本語の表示名で出す（例：「接触の種類：Visit（訪問）」「危険度：LifeThreatening（生命に関わる）」）。承認の対象になる 16 種の、show に出る項目すべてに名前がある。正典の項目・必須・列挙値は変えていない。試験は `tests/test_semantics_field_names.py`
- **4.5 (b) の画面の書き方を、実際に通った手順に合わせた。** 上の表の 4 に書いた「フォルダーを選ばせる画面は Claude Code で nest-gate がつながっていない」は**誤り**で、手順書から外した。今は、アプリで「新規作成」→ 入力欄の下の「プロジェクトまたはフォルダー」は何も選ばない → 右下は「手動」のまま送る、と書いている。区別として残したのは「ターミナルで `claude` と打って起動したものには nest-gate がつながっていない」だけ。フォルダーを選んだ場合のことは確かめていないので書いていない
- 「手動」のままなら、道具を呼ぶたびに許可を求められる。手順書に「許可を求められたら、仮名を確かめてから許可する」を足した

## 追記：根拠が未確定のまま禁忌・面接記録が有効になった（2026-11-11 河原さんの報告）

- 起きたこと：`review_proposals.py approve` で NGA-…92 と SLG-…PH を承認したら Active になったが、根拠の記録 REC-…FMFJ9 は Pending のままだった。道具は何も言わずに通した
- 判断：河原さんの案（根拠を一緒に承認する）は、正典 §7「AI 由来のノードをまとめて一括で承認しない（一回の操作で一つのノード）」と ADR-001 D9「事実ごとに承認する」に合わない。**もう一つの考え（先に根拠を承認させる）を採った。正典は変えていない**
- 直したこと（`nest/gate/approve.py`）：承認のとき、根拠（`EVIDENCED_BY` の先の記録）に未確定のものがあれば止め、先に承認する記録の ID を名指す（何も変えず、AuditLog も残さない）。根拠がすべて差し戻し済みなら止める。根拠の一部だけが差し戻し済みで、残りが有効なら通す（差し戻した根拠を理由に、ずっと承認できなくなるのを避けた）。差し戻しは止めない
